# Code Quality & UI Modernization Plan

Living plan for bringing the codebase in line with Laravel best practices and migrating the UI to Tailwind CSS v4. Work it top to bottom, one phase (or one batch inside a phase) at a time, and tick items off as they land.

**Status legend:** `[x]` done · `[ ]` to do · `[~]` in progress · `[-]` deferred

**Rules for every batch**

- Keep each batch small and independently shippable: one concern, its tests, green suite.
- Behavior must not change unless the item says so. Existing tests are the safety net; add tests where a fix changes or protects behavior.
- Definition of done: `vendor/bin/pint --dirty --format agent`, the full suite passing (`php artisan test --compact`), `npm run build` if frontend files changed, and this file updated.

## Phase 7 — Enums (large, highest risk)

Replace the stored status, role and path strings with string-backed enums and Eloquent enum casts, one domain per batch. Started with the user's approval (2026-10-21); planned 2026-10-22 against Laravel 13.30.1 and PHP `^8.3`. Reference counts below are approximate (grep, 2026-10-22).

**Phase 7 rules** (every batch)

- **Location and creation.** Enums live in `app/Enums` (a new base folder; see the open questions). Create them with `php artisan make:enum Enums/{Name} --string --no-interaction`: until `app/Enums` exists, a bare `make:enum {Name}` writes `app/{Name}.php`.
- **Names and values.** Singular domain names (`SubmissionStatus`, `UserRole`, `TrainingPath`), string-backed, TitleCase cases whose values are the exact stored strings (`NeedsRevision = 'needs_revision'`), so no data migration and no migration edit is needed. Every column involved is a plain `string` (no MySQL `ENUM` in any migration), so the schema does not change. Every value the code can store or read gets a case, including values that only a column default or legacy rows produce (named per batch). Cast with `'column' => {Enum}::class` in the model's `casts()`.
- **One source.** Replace the model constants with enum cases in the same batch and update every reference; keep no constants or aliases beside the enum. Reused subsets become named static methods returning `list<self>` (e.g. `GoogleDriveExportStatus::active()` for `GoogleDriveExport::ACTIVE_STATUSES`). The `CLAUDE.md` "Status and role values" rule still names the model constants; once a domain's batch lands, its enum replaces them (the close-out batch proposes new wording).
- **Labels.** `label(): string` holds the generic display text the app shows today (usually `ucfirst(str_replace('_', ' ', $value))`, or an existing model map such as `User::TRAINING_PATHS`). Surfaces that show different text today keep it (their own map keyed by `->value`, or a `match` on the case). Change label text only in a batch that resolves a recorded open decision after the user has chosen the text. Select options come from `cases()` in the page service (`['value' => $case->value, 'label' => $case->label()]`).
- **Validation.** In Form Requests use `Rule::enum({Enum}::class)` when the accepted set equals the cases and `Rule::enum(...)->only([...])` for a subset; filters that mix domains (the review queue and coach report `status`) use `Rule::in([...])` built from both enums' cases. The default `enum` and `in` messages are identical ("The selected :attribute is invalid.") and no Form Request has a custom `.in` message today (if one appears, rename its key to `.enum`). Read validated input as a case (`$request->enum('status', GateEvaluationStatus::class)`) instead of comparing strings.
- **Cast traps.** After a cast the attribute is an enum object. `=== 'x'`, `!== 'x'`, `in_array($model->status, ['x'], true)`, `match ($model->status) { 'x' => … }`, `@if($model->status === 'x')` and `@selected(old('f', $model->f) === $value)` silently stop matching (a `match` falls to `default` or throws `UnhandledMatchError`); compare against cases (`@use('App\Enums\…')` in views, or prepare the value in the page service). Using the attribute as an array key (`$tones[$model->status]`), in `ucfirst` / `str_replace` / `strtoupper`, string interpolation or concatenation, `implode` or `fputcsv` throws; use `label()` or `->value` (exports and CSVs print `->value`, so their output does not change). Collection `where` / `firstWhere` / `groupBy` unwrap enums, but `whereIn` / `contains` with string lists and `countBy` closures that return a case do not. A variable must not mix cases and strings (`$evaluation?->status ?? 'ready_for_review'`). Unaffected: `{{ $model->status }}` (`e()` prints a backed enum's value), JSON (serializes the value), query-builder bindings (`where`, `whereIn`, `update`, `updateOrCreate` accept cases through `enum_value()`), and assigning a valid backing string (so request payloads, `create([...])` arrays and `assertDatabaseHas` keep working). Reading or assigning a value that is not a case throws `ValueError`.
- **Left alone.** Migrations (history), and `resources/js`, which reads form values and JSON and so keeps the raw backing values (Blade `value=""` attributes print `->value`). The untracked `database/seeders/L4TrainingProgramSeeder.php` holds none of these values and is not edited. Derived, never-stored keys that share a word with a domain (filter keys such as `scored` or `active`, `WeekTwoGateService::weeklyVideo()`'s `missing` / `met` / `awaiting_review`, the evidence context `inspected`) are not enum values.
- **Wide domains** split into "cast + every read the cast breaks" and then "sweep the remaining literals" (writes, query bindings, validation lists, factories, seeders, config). Assigning backing strings still works after the cast, so both halves leave the suite green. A shared helper that takes `string $status` from two domains (`ActivitySubmissionPageService::statusLabel()` / `statusTone()` serve version statuses and review decisions) receives `->value` from whichever domain is cast first; the later batch types it with the enums and drops the `->value`.
- **Tests.** Assertions on model attributes compare cases (`assertSame(SubmissionStatus::Failed, $submission->fresh()->status)`); HTTP payloads, JSON assertions, `assertDatabaseHas` and `create([...])` attribute arrays may keep the stored strings (they test the wire and storage format); factory definitions use cases. Add a test only where a batch changes behavior or no existing test reads the cast attribute.
- **Before a cast ships,** its columns must pass the production value check under "Phase 7 open questions": the suite runs on empty in-memory SQLite and cannot catch an unexpected stored value.
- **Definition of done** (on top of the plan's): the domain's constants are gone (`grep -rn '{Model}::{CONST}' app resources routes config database tests` is empty), and a grep proof shows no raw literal of the domain outside migrations: `grep -rnE "'(value1|value2|…)'" app resources/views routes config database/factories database/seeders` (minus the L4 seeder; for roles, also check the `role:` route parameters), with every remaining hit justified in the done note (another domain's identical word, a derived key, a surface label). `npm run build` when a view or JS file changed.
